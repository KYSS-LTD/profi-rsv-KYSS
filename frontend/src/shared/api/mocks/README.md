# Демо-моки фронтенда

Слой демо-данных, чтобы интерфейс можно было показать **без бэкенда и без логина**.
Включён по умолчанию — у всех, кто развернёт сервис локально, сразу будут данные на всех страницах.

## Как это работает

- `enabled.ts` — единственный флаг `MOCKS_ENABLED` (по умолчанию `true`).
- `data.ts` — связный демо-набор (сотрудники, отделы, задачи, аналитика, карта оргструктуры и т.д.).
- `index.ts` — `resolveMock(method, path, body)` сопоставляет запрос с данными; `bootstrapMocks()` сеет демо-токен.
- Подключение: один `if (MOCKS_ENABLED)` в `src/shared/api/client.ts` и `bootstrapMocks()` в `src/main.tsx`.

GET читает данные, POST/PATCH/DELETE мутируют коллекции в памяти (живут в рамках сессии, без персистентности).

## Как убрать моки

Любой из способов:

1. **Через окружение (ничего не меняя в коде):**
   ```bash
   VITE_USE_MOCKS=false npm run dev      # или npm run build
   ```
   Для docker — добавить `VITE_USE_MOCKS=false` в build-args фронтенда.

2. **Поменять значение по умолчанию** в `enabled.ts` на `false`.

3. **Удалить полностью:** удалить папку `src/shared/api/mocks`, затем снять перехват
   в `src/shared/api/client.ts` (блок `if (MOCKS_ENABLED) { ... }` и два импорта)
   и вызов `bootstrapMocks()` в `src/main.tsx`.

> Прототип созвонов на странице «Мои задачи» (`src/widgets/Meetings/CallsView.tsx`
> + `mockCalls.ts`) — отдельный статический мок и от этого слоя не зависит.
